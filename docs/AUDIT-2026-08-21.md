## 3. Temuan Kritis (P0) — Detail & Handling

### 3.1 Rantai kehilangan data pada storage (paling berbahaya)

**Masalah.** `FinanceStorage._decodeList` dan `ReminderStorage.load` menangkap *semua* error decode dengan `catch (_) { return []; }`. Dikombinasikan dengan:

1. `ExpenseEntry.fromJson` melakukan hard-cast `json['id'] as String` → **satu** entry tanpa `id` melempar exception,
2. `_loadData()` memanggil `materializeDueRecurring()` lalu **langsung `saveExpenses()`**,

maka satu data rusak → seluruh list terbaca kosong → pengeluaran berulang "diregenerasi" ke list kosong → **seluruh riwayat pengeluaran pengguna tertimpa permanen**. Ini bukan skenario hipotesis: data `shared_preferences` bisa rusak karena proses terputus saat penulisan.

**Handling (sudah diterapkan):**
- Data rusak total → salinan mentah **dikarantina** ke kunci `<key>_corrupt` (tidak pernah dibuang diam-diam), dilaporkan lewat `StorageCorruptionReport`.
- Kegagalan **per-entry** diisolasi: entry sehat tetap dimuat, hanya entry rusak yang dilewati (juga dikarantina + dilaporkan `partial`).
- `_loadData()` **menahan auto-save recurring** jika ada data yang tidak terbaca, dan menampilkan dialog rekomendasi restore.
- `fromJson` semua model jadi defensif: ID hilang → fallback ID **deterministik dari konten** (`expense_recovered_<hash>`) sehingga merge restore tidak menduplikasi entry yang sama.

**Sisa risiko & rekomendasi lanjutan:** `shared_preferences` tetap bukan database. Untuk jangka panjang lihat §6 (sqlite/drift).

### 3.2 Backup tidak bisa direstore di HP lain — menggagalkan tujuan backup

**Masalah.** `.bibzcup` ditandatangani HMAC-SHA256 dengan kunci dari `flutter_secure_storage` (keystore perangkat, `scope="device-keystore"`). Di perangkat lain verifikasi selalu gagal → error *"backup telah berubah atau bukan dibuat oleh perangkat ini"*. Artinya: **HP hilang/rusak = backup di Google Drive tidak bisa dipakai di HP baru** — tepat pada skenario backup paling penting.

**Handling (sudah diterapkan):** dua tingkat verifikasi.
- Tingkat 1 (default): verifikasi signature perangkat, ketat, seperti sebelumnya.
- Tingkat 2 (baru): bila signature tidak cocok, dilempar `CrossDeviceBackupException` yang membawa path file; UI menawarkan dialog konfirmasi eksplisit ("Lanjutkan restore?"). Bila disetujui, restore lanjut **tanpa** signature perangkat tetapi **dengan verifikasi penuh checksum SHA256 seluruh file** dalam arsip terhadap manifest (zip-slip, file tak terdaftar, file hilang, konten berubah → semuanya tetap ditolak).

**Trade-off yang disadari:** checksum berada di manifest yang tidak lagi ditandatangani pada mode ini, jadi penyerang yang bisa *menulis ulang kedua file* secara konsisten lolos. Untuk model ancaman aplikasi lokal ini risikonya dapat diterima dan merupakan peningkatan besar dibanding "tidak bisa restore sama sekali".

**Rekomendasi lanjutan (stage 2):** signature tambahan berbasis **passphrase** (PBKDF2 → HMAC) yang dipilih pengguna saat backup; membuat backup portabel sekaligus terverifikasi di perangkat mana pun.

### 3.3 Self-updater tanpa verifikasi integritas APK

**Masalah.** Alur updater: ambil `version-latest.json` dari GitHub → unduh APK dari URL di metadata → panggil `install_apk` native → Android installer. Tidak ada satu pun verifikasi bahwa APK yang diunduh adalah APK yang dimaksud. Jika akun GitHub/repo/metadata disusupi (atau redirect di-spoof), aplikasi dengan senang hati mengunduh dan memasang APK arbitrer — pengguna hanya dilindungi oleh konfirmasi installer Android.

**Handling — 3 lapis (sudah diterapkan):**
1. **Allowlist URL (Dart):** hanya `https` + host GitHub resmi (`github.com`, `*.githubusercontent.com`, dst). `http://`, host asing, dan host menyerupai-GitHub-palsu ditolak sebelum ada koneksi.
2. **Checksum opsional (Dart):** `version-latest.json` kini mendukung `sha256Universal`/`sha256Arm64` (dengan fallback nama lama); bila ada, digest APK unduhan wajib cocok — file mismatch langsung dihapus.
3. **Verifikasi sertifikat signing (Kotlin, pertahanan terakhir):** sebelum `ACTION_VIEW` installer, `MainActivity` membandingkan sertifikat APK unduhan (`getPackageArchiveInfo`) dengan sertifikat aplikasi terpasang. APK yang ditandatangani kunci lain → ditolak dengan error jelas. Ini mempertahankan jaminan identitas paksaan-update tidak bisa mengganti identitas aplikasi.

**Rekomendasi lanjutan:** workflow `android-release.yml` sudah menghasilkan `SHA256SUMS.txt`; langkah berikutnya adalah mempublikasi hash ke `version-latest.json` otomatis pasca-release (app sudah siap memverifikasinya).

### 3.4 Dependabot tidak pernah aktif

**Masalah.** `.github/dependabot.yml` berisi `package-ecosystem: ""` — nilai kosong tidak valid; Dependabot menolak konfigurasi dan **tidak pernah membuat PR update** sejak file itu dibuat.

**Handling (sudah diterapkan):** tiga ekosistem nyata — `github-actions` (mingguan, digroup), `pub` (beta, `enable-beta-ecosystems: true`, batas 5 PR), dan `gradle` untuk `/android`. Catatan dibenamkan di file: dependency path/git (mis. `vendor/file_picker`) tetap dirawat manual.

## 4. Temuan Penting (P1) — Detail & Handling

### 4.1 Undo hapus mengembalikan lampiran menggantung
`_deleteExpense`/`_deleteDebt` menghapus file foto **segera**, lalu menawarkan URUNGKAN yang mengembalikan entry — dengan `imagePath` menunjuk file yang sudah tidak ada. **Fix:** file dihapus **setelah** jendela undo berlalu (timer 6 detik, dibatalkan bila undo ditekan / page unmount).

### 4.2 Feed gambar dashboard dari Pastebin
`ImageFeedService` mengambil daftar URL gambar dari `pastebin.com/raw/...`. Siapa pun yang menguasai akun pastebin itu mengontrol konten dashboard semua pengguna (dan pastebin melihat IP semua pengguna). Validasi https+ekstensi sudah bagus, tetapi kanal kontrolnya salah tempat. **Fix:** sumber pindah ke `dashboard-feed.txt` di repo aplikasi (raw GitHub) — jalur pembaruan konten sejalan dengan jalur kode; isi awal sama persis dengan isi pastebin lama.

### 4.3 Dead code
`lib/services/task_storage.dart` (tidak direferensikan di mana pun) dan `ThemeSettingsSheet` di main.dart (diduplikasi fungsinya oleh `AppSettingsSheet`) — **dihapus**. `lib/models/task_item.dart` awalnya ikut dihapus, namun dipulihkan pada merge karena commit hardening owner menambahkan `test/model_parsing_test.dart` yang mengujinya; model ini tetap belum dipakai UI — kandidat dihapus/disambungkan di stage 2.

> **Catatan koordinasi:** saat PR ini disusun, maintainer mendorong commit hardening sendiri ke `main` (`json_helpers.dart`, `roundMoney`, antrean tulis, cache bounds gambar, handler error global). Kedua karya digabung penuh pada commit merge: hardening owner diterapkan ke struktur modular baru (roundMoney di `FinanceCalc`, cache bounds di `finance_tiles`/`form_scaffolding`, antrean tulis di `FinanceStorage` berdampingan dengan karantina korupsi), dan fallback ID digabung — toleran id numerik lama (`42` → `'42'`, gaya owner) sekaligus deterministik untuk id yang hilang (gaya PR ini, anti-duplikasi saat merge restore).

### 4.4 Label kategori tidak konsisten
Ada dua definisi `categoryLabel` dengan label berbeda ("Makan" di sheet anggaran, "Makanan" di export/main). **Fix:** dipusatkan sebagai extension `ExpenseCategoryLabel` di `models/finance_models.dart`; UI, Excel, dan PDF kini konsisten.

### 4.5 Guard `mounted` dan komentar basi
`_showExpenseForm`/`_showDebtForm` memanggil `setState` setelah `await` tanpa cek `mounted` → potensi exception saat sheet menutup bersamaan dengan page unmount. Ditambah guard. Komentar yang merujuk package yang sudah diganti (`excel_plus` → `excel`) dikoreksi.

### 4.6 Fitur "Backup ke Google Drive" tidak bisa diakses (ditemukan saat merge)
`_backupToGoogleDrive()` di main.dart (dan didokumentasikan di README) **tidak dipanggil oleh UI mana pun** — sheet Pengaturan hanya menyambungkan `onBackup` (backup lokal) dan `onRestore`. Fitur telah tersambung kembali sebagai aksi "Backup ke Google Drive" di sheet Pengaturan (opsional; hanya tampil bila callback disediakan).

## 5. Arsitektur (P2) — Stage 1 Selesai

**Sebelum:** `main.dart` 4.698 baris berisi semuanya — tema, splash, state halaman, 20+ widget, form, kalkulator, sheet komunikasi, dan semua helper. Global mutable `_privacyMode` dibaca oleh formatter mata uang.

**Sesudah (stage 1):**

```
lib/
  main.dart                    # entry + app + home state (2.750 baris, turun 42%)
  core/
    palette.dart               # warna desain (satu sumber kebenaran)
    format.dart                # PrivacyMask + formatCurrency/parseAmount/newId/formatDate
    categories.dart            # ikon & warna kategori
  forms/
    expense_form_sheet.dart    # form pengeluaran
    debt_form_sheet.dart       # form hutang/piutang
  widgets/
    finance_tiles.dart         # kartu/tile yang dipakai halaman utama
    form_scaffolding.dart      # SheetShell, lampiran foto, pemilih sumber
    communication_sheet.dart   # WhatsApp/SMS + template pesan
    calculator_sheet.dart      # kalkulator cepat + evaluator ekspresi
    entry_actions.dart         # konfirmasi hapus + alur edit foto
  services/finance_calc.dart   # perhitungan murni (totals, merge akun, reminder id)
```

- `_privacyMode` global → `PrivacyMask.enabled` terpusat (satu titik tulis/baca).
- `FinanceCalc` berisi logika murni tanpa Flutter — bisa dan sudah diuji unit-test.
- Tidak ada widget lain yang meng-import `main.dart` (dipastikan), sehingga semua pemindahan satu arah dan aman.

**Stage 2 (roadmap, jangan dikerjakan sekaligus):**
1. Angkat `_FinanceHomePageState` menjadi `ChangeNotifier`/controller + repository per agregat (expenses, debts, savings) — pecah method build per tab menjadi widget terpisah dengan parameter eksplisit.
2. Naikkan `SharedPreferences` ke `drift`/`sqflite` (query bulanan/anjuran jadi murah; tulis atomik; tidak lagi rewrite seluruh JSON per save).
3. Signature passphrase untuk backup portabel (lihat §3.2).
4. Ganti API deprecated Flutter (`DropdownButtonFormField.value` → `initialValue`, `Radio.group` → `RadioGroup`, `pw.Table.fromTextArray` → `TableHelper`, `XmlText.text` → `XmlData.value`) — daftar lengkap bisa diambil dari `flutter analyze` tanpa `--no-fatal-infos`.
5. Pertegas CI: setelah deprecation habis, jalankan analyze tanpa `--no-fatal-infos`.

## 6. Keputusan yang Disengaja Tidak Diubah (beserta alasannya)

| Item | Kenapa dibiarkan | Kapan perlu diubah |
|---|---|---|
| `MANAGE_EXTERNAL_STORAGE` | Distribusi sideload; izin ini yang membuat backup langsung menulis ke `/sdcard/Documents/CatatBibz` tanpa SAF. | Bila ke Play Store (kebijakan sangat membatasi izin ini): migrasi ke MediaStore/SAF atau folder app-specific + share sheet. |

| Release CI `--no-shrink --no-tree-shake-icons` | Trade-off kecepatan rilis yang disengaja & terdokumentasi di workflow. | Bila ukuran APK jadi masalah: build terpisah "optimized" mingguan. |
| Folder `ios/` & `web/` | CI build web lulus; iOS bukan target rilis. | Putuskan: rawat atau hapus total agar tidak menyesatkan. |
| `gradle.properties` single-worker/SerialGC | Tuning environment build terdokumentasi. | Bila build lokal di mesin kuat. |

## 8. Catatan Untuk Rilis Berikutnya

1. `version-latest.json` — pertimbangkan menambah `sha256Universal`/`sha256Arm64` (aplikasi sudah memverifikasinya otomatis bila ada).
2. Setelah PR ini digabung, tag rilis baru diperlukan agar pengguna versi lama menerima perbaikan lewat updater (ingat: updater membandingkan `versionCode`).
3. Backup yang dibuat sebelum PR ini tetap kompatibel — restore lintas perangkat berlaku juga untuk file lama.
